# PROMPT CLAUDE — MIGRASI INBOX GMAIL → GHL API (SEND DARI WEB)

## TUJUAN

Migrasikan **hanya fitur Inbox** dari Gmail menjadi menggunakan **GoHighLevel (GHL) sebagai sumber data/API**.

Namun ada satu aturan penting:

> **GHL hanya digunakan sebagai API/data source. Agent tetap membaca dan mengirim pesan langsung dari website Laravel ini.**

Jadi website Laravel adalah workspace utama agent.

### TARGET

```text
GHL
  ↓
API
  ↓
Laravel Inbox
  ↓
Agent membaca conversation
  ↓
Agent menulis reply di website
  ↓
Laravel mengirim reply melalui GHL API
  ↓
Pesan masuk ke conversation/contact tujuan di GHL
```

Agent **tidak perlu membuka GHL untuk mengirim pesan.**

- messages
- contacts
- contact details
- channel
- timestamps
- unread/status jika tersedia
- assigned user jika tersedia
- metadata yang relevan dengan Inbox

Laravel juga menggunakan GHL API untuk:

- mengirim reply;
- melakukan action conversation yang memang dibutuhkan Inbox.

Tetapi:

**Semua aktivitas agent dilakukan dari website Laravel.**

Jangan membuat agent diarahkan ke GHL.

Jangan membuka GHL dalam iframe.

```text

```

# 4. SEND MESSAGE — SANGAT PENTING

Saat agent menulis:

```text
Halo, bagaimana saya bisa membantu?
```

lalu klik:

```text
Send
```

alur harus:

```text
Laravel Inbox
    ↓
InboxController
    ↓
GHL Service
    ↓
GHL API
    ↓
Conversation/contact
    ↓
Message terkirim
```

Bukan:

```text
Laravel
 ↓
redirect ke GHL
 ↓
agent kirim dari GHL
```

dan bukan:

```text
Laravel
 ↓
Gmail API
```

### Agent harus bisa melakukan semuanya dari Laravel.

Setelah message berhasil:

1. tampilkan message di conversation;
2. update conversation state;
3. clear textarea;
4. tampilkan status sukses;
5. handle error jika gagal;
6. jangan duplicate message.

---

# 5. JANGAN MENGARANG API GHL

Audit dokumentasi/API yang sudah digunakan project terlebih dahulu.

Jangan menebak:

- endpoint;
- HTTP method;
- request body;
- response format;
- field;
- scope.

Jika project sudah memiliki:

```text
GoHighLevelApiService
```

gunakan dan extend service tersebut bila memungkinkan.

Jangan membuat service duplikat.

Jika endpoint Send Message membutuhkan endpoint/permission tertentu, gunakan implementasi GHL yang valid.

Jika menemukan:

```text
401
403
404
422
429
5xx
```

diagnosis dengan benar dan jangan membuat workaround palsu.

# 6. KONFIGURASI GHL

Gunakan Private Integration yang sudah dibuat.

Konfigurasi minimal:

```env
GHL_API_KEY=
GHL_LOCATION_ID=
GHL_BASE_URL=
```

Jika project sudah mempunyai sistem Settings untuk konfigurasi GHL, gunakan sistem tersebut.

Jangan membuat konfigurasi baru jika tidak diperlukan.

API key:

- jangan hardcode;
- jangan expose ke frontend;
- jangan dikirim ke JavaScript;
- jangan tampilkan di Blade;
- jangan log token.

Frontend Laravel hanya memanggil endpoint Laravel sendiri.

Contoh:

```text
Browser
  ↓
POST /inbox/{conversation}/messages
  ↓
Laravel
  ↓
GHL API
```

Browser **tidak boleh langsung memanggil GHL API menggunakan Private Integration token.**

# 21. ACCEPTANCE CRITERIA

Migrasi dianggap selesai jika:

- [ ] Inbox tidak lagi mengambil data dari Gmail.
- [ ] Conversation diambil dari GHL API.
- [ ] Message/thread diambil dari GHL API.
- [ ] Contact information diambil dari GHL API.
- [ ] Agent dapat membaca conversation dari Laravel.
- [ ] Agent dapat mengetik reply di Laravel.
- [ ] Agent dapat menekan Send dari Laravel.
- [ ] Laravel mengirim message melalui GHL API.
- [ ] Agent TIDAK perlu membuka GHL untuk mengirim.
- [ ] GHL Private Integration token hanya berada di backend.
- [ ] Tidak ada GHL token di frontend.
- [ ] Message berhasil muncul kembali di Inbox setelah dikirim.
- [ ] Existing AI Process tetap bekerja.
- [ ] Existing AI Summary/Translate/Draft tetap bekerja jika sudah ada.
- [ ] Gmail-specific Inbox dependency sudah dihapus jika memang tidak digunakan lagi.
- [ ] Fitur di luar Inbox tidak berubah.
