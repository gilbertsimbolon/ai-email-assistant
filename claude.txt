# PROMPT CLAUDE — MIGRASI INBOX MENJADI GHL DIRECT / REALTIME TANPA DATABASE CONVERSATIONS

## TUJUAN UTAMA

Ubah architecture Inbox/Conversations Laravel agar **tidak lagi melakukan sinkronisasi conversation/message GHL ke database Laravel**.

GHL menjadi **satu-satunya source of truth** untuk seluruh data Conversations.

Laravel hanya menjadi:

- workspace agent
- UI Inbox/Conversations
- API proxy/backend ke GHL
- tempat agent membaca conversation
- tempat agent mengirim message
- tempat menjalankan fitur AI secara on-demand

Database Laravel **tetap digunakan untuk konfigurasi aplikasi yang memang membutuhkan persistence**, misalnya:

- AI Configuration
- OpenAI API configuration
- AI Center
- SOP
- Rules
- Templates
- User
- Role/Permission
- Settings lain yang memang merupakan data aplikasi

Tetapi:

> **JANGAN simpan Conversation GHL atau Message GHL ke database Laravel.**

---

# 1. SCOPE — HANYA INBOX / CONVERSATIONS

Fokus task ini hanya pada:

1. Inbox/Conversations
2. GHL API integration untuk Conversations
3. realtime/near-realtime data
4. send message dari Laravel ke GHL
5. tampilan Inbox menyerupai GHL
6. fitur agent seperti:
   - thread summary
   - translate
   - AI assistance
   - informasi contact
   - informasi conversation
   - metadata yang tersedia dari GHL

Jangan mengubah fitur lain yang tidak berhubungan dengan Inbox.

# 6. JANGAN HAPUS GOHIGHLEVEL API SERVICE

`GoHighLevelApiService` harus menjadi gateway utama komunikasi Laravel → GHL.

Pertahankan:

```text

GHL Location ID
GHL Base URL
GHL API Version
```

dari `.env`/config.

Pastikan token tidak pernah dikirim ke browser.

Browser hanya berkomunikasi dengan Laravel.


```text

last message
```

Jangan mempertahankan stale local copy.

# 10. REALTIME / NEAR REALTIME

Target:

> Apa pun yang baru masuk di GHL harus muncul di Laravel tanpa agent melakukan refresh manual.

Contoh:

```text
Customer mengirim message
        ↓
GHL
        ↓
Laravel mengambil data terbaru
        ↓
Conversations UI
        ↓
Message muncul
```

## PRIORITAS

Pertama audit apakah GHL Private Integration Token yang sedang digunakan mendukung webhook/event yang dibutuhkan.

Jangan mengarang kemampuan webhook.

Jika webhook benar-benar tersedia dan bisa digunakan dengan authentication sekarang:

```text
GHL Event
 ↓
Laravel webhook
 ↓
trigger frontend update
```

Tetapi jika PIT tidak bisa digunakan untuk webhook yang diperlukan:

**JANGAN mengganti architecture authentication.**

Gunakan frontend polling langsung ke Laravel.

# 37. ACCEPTANCE CRITERIA

Task hanya dianggap selesai jika:

### UI

- [ ] Inbox menggunakan layout 3 kolom.
- [ ] Kolom kiri = Conversations.
- [ ] Kolom tengah = Message Thread.
- [ ] Kolom kanan = Contact/Conversation Details.
- [ ] UI mengikuti informasi dan struktur GHL semaksimal mungkin berdasarkan data API yang tersedia.
- [ ] Search tersedia.
- [ ] Loading state tersedia.
- [ ] Error state tersedia.

### GHL Data

- [ ] Conversations berasal langsung dari GHL API.
- [ ] Messages berasal langsung dari GHL API.
- [ ] Contact information berasal dari GHL.
- [ ] Conversation metadata berasal dari GHL.
- [ ] Tidak menggunakan MySQL sebagai source Inbox.

### Realtime

- [ ] Conversation baru di GHL muncul di Laravel otomatis.
- [ ] Message baru di GHL muncul di Laravel otomatis.
- [ ] Agent tidak perlu F5.
- [ ] Tidak terjadi duplicate message.
- [ ] Polling hanya berjalan ketika diperlukan.
- [ ] Active conversation mendapatkan message terbaru.

### Sending

- [ ] Agent dapat mengirim message dari Laravel.
- [ ] Message dikirim melalui GHL API.
- [ ] Setelah send berhasil, UI mengambil data terbaru dari GHL.
- [ ] Tidak menyimpan sent message ke database Laravel.

### AI

- [ ] Summary thread tersedia.
- [ ] Translate tersedia.
- [ ] AI Process tetap manual/on-demand.
- [ ] AI configuration tetap menggunakan database.
- [ ] Conversation tidak disimpan untuk keperluan AI.

### Database

- [ ] Tidak ada Conversation GHL baru yang dibuat di database.
- [ ] Tidak ada Message GHL baru yang dibuat di database.
- [ ] Tidak ada GHL sync job yang menyimpan conversation ke database.
- [ ] Database hanya digunakan untuk application data seperti AI Configuration, users, roles, SOP, rules, templates, settings, dll.

## INSTRUKSI TERAKHIR

Jangan memperumit architecture.

Saya **tidak membutuhkan local copy/cache/database untuk Conversations**.

Saya ingin Laravel bertindak sebagai:

> **Custom agent workspace di atas GHL API.**

Prioritaskan:

1. **data GHL yang selalu aktual**
2. **realtime/near-realtime**
3. **UI mirip GHL**
4. **send message langsung dari Laravel ke GHL**
5. **AI tools untuk membantu agent**
6. **tanpa menyimpan Conversations/Messages GHL ke database**
