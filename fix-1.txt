Kamu adalah Senior Software Architect, Senior Laravel Developer, dan SaaS System Designer.

Saya ingin mengubah cara konfigurasi Gmail API pada project ini.

Saat ini aplikasi masih membaca konfigurasi Gmail dari file .env.

Saya ingin mengubah arsitektur tersebut agar seluruh konfigurasi Gmail dapat diatur melalui halaman Settings pada aplikasi (frontend/admin panel), tanpa perlu mengubah file .env lagi.

==================================================
TUJUAN
==================================================

Seluruh konfigurasi Gmail OAuth harus bersifat dinamis.

Administrator dapat mengubah konfigurasi langsung dari halaman Settings.

Aplikasi harus langsung menggunakan konfigurasi terbaru tanpa perlu restart aplikasi atau mengedit .env.

==================================================
YANG HARUS DILAKUKAN
==================================================

Lakukan audit seluruh project.

Cari semua bagian yang membaca:

config('services.google')

config('gmail')

env('GOOGLE_CLIENT_ID')

env('GOOGLE_CLIENT_SECRET')

env('GOOGLE_REDIRECT_URI')

Google Client yang di-hardcode

hapus ketergantungan tersebut dan ubah agar membaca konfigurasi dari database.

==================================================
DATABASE
==================================================

Buat tabel baru apabila belum ada.

Contoh:

gmail_settings

id

client_id

client_secret

redirect_uri

enabled

created_at

updated_at

atau gunakan tabel settings apabila project sudah memiliki Global Settings.

Gunakan struktur database yang paling sesuai dengan project.

==================================================
MODEL
==================================================

Buat model:

GmailSetting

atau gunakan model Setting apabila sudah tersedia.

==================================================
SERVICE
==================================================

Buat service khusus.

Misalnya:

GmailConfigurationService

Service ini bertugas mengambil konfigurasi Gmail dari database.

Jangan membaca langsung dari env().

==================================================
GOOGLE CLIENT
==================================================

Saat membuat Google\Client, konfigurasi harus berasal dari database.

Contoh alur:

Database

↓

GmailConfigurationService

↓

Google\Client

Bukan lagi:

.env

↓

config

↓

Google\Client

==================================================
SETTINGS PAGE
==================================================

Buat halaman konfigurasi Gmail.

Field:

Google Client ID

Google Client Secret

Redirect URI

Enable Gmail Integration

Test Connection

Save Configuration

Tambahkan validasi.

==================================================
TEST CONNECTION
==================================================

Tambahkan tombol:

Test Connection

Saat ditekan:

- validasi konfigurasi
- buat instance Google Client
- cek apakah konfigurasi valid
- tampilkan pesan berhasil atau gagal

Jangan menyimpan token.

Hanya menguji konfigurasi OAuth.

==================================================
OAUTH LOGIN
==================================================

Saat user menghubungkan akun Gmail.

Jangan membaca konfigurasi dari env.

Gunakan konfigurasi dari database.

==================================================
TOKEN
==================================================

Konfigurasi Gmail bersifat global.

Sedangkan:

Access Token

Refresh Token

Expiry

tetap disimpan per akun Gmail.

Jangan mencampurkan konfigurasi global dengan token user.

==================================================
SECURITY
==================================================

Client Secret wajib disimpan secara aman.

Gunakan encryption Laravel apabila diperlukan.

Jangan pernah mengirim Client Secret ke frontend kecuali saat memang diperlukan untuk pengisian form administrator.

Pastikan hanya administrator yang dapat mengakses halaman konfigurasi Gmail.

==================================================
BACKWARD COMPATIBILITY
==================================================

Apabila belum ada konfigurasi di database.

Gunakan nilai dari .env sebagai fallback sementara.

Namun setelah konfigurasi berhasil disimpan melalui halaman Settings.

Seluruh proses harus menggunakan data dari database.

==================================================
REFACTOR
==================================================

Lakukan refactor terhadap seluruh bagian project yang masih bergantung pada konfigurasi Gmail dari .env.

Pastikan tidak ada pembacaan konfigurasi Gmail secara langsung menggunakan env() di dalam controller, service, job, listener, middleware, maupun helper.
